# Chrome extension compatibility evidence

Date: 23 October 2026. Scope: the incorrect extension names and Are.na Incompatible state reported in Settings, plus the missing local language API used by Google Translate. These checks use temporary nonpersistent controllers and synthetic page text. No real browser data, account, login or content posting was used.

## Findings and changes

| Finding | Change | Evidence |
| --- | --- | --- |
| Install replaced every `__MSG_*__` name with the extension ID. Updates retained the incorrect saved name. | `ExtensionManifest.displayName` resolves the current locale, base language and `default_locale`, with per-message fallback and case-insensitive keys. Static message placeholders and escaped dollars work; unsupported positional substitutions use a valid fallback. Install/update/reload use the result. `Extensions.refreshInstalledNames` refreshes retained records after the first frame, off the main actor, including disabled extensions. Missing packages keep the retained name. | Nine `ExtensionLocalizationTests`; current public-package name inspection below. |
| Failed extension records held only the extension version, so an older engine failure survived later fixes. | `ExtensionCheckEnvironment` scopes failure records to the extension version, macOS build, Safience version/build and shim/preparation stamp. Legacy or stale markers expire without changing enabled spaces or retained extension data. Genuine failures in the same environment remain blocked. | Three `ExtensionCheckEnvironmentTests`. |
| WebKit retains old errors and consolidates repeats. Repeated notifications could repeatedly schedule a restart, then interpret the cooldown refusal as another failed restart and disable the extension. | `ExtensionWorkerRecovery` lets a historical error request one restart. Only a specific restart's own thrown load or failed completion establishes repeated failure. Cooldown/deferred attempts and duplicate notifications cannot establish incompatibility. Load/restart callbacks verify current attempt/context identity before changing watches or status. | Four `ExtensionWorkerRecoveryTests`: duplicate history after success, a confirmed failed restart, stale completions and deferred/cooldown requests. |
| Native WebKit lacked `i18n.detectLanguage`, used by Translate. | The team added a text-only shim endpoint backed by local `ExtensionLanguage` recognition. The endpoint does not read a page, use an account or grant additional host access. Authorized tab-language sampling remains owned by Page and checks its current grant/identity. | Actual Are.na and Translate workers receive Chrome-shaped results for a literal English sentence through the current production shim and real native helper. The language owner's native fixtures separately cover recognition and authorized page sampling. |

## Public package inspection

Packages came from Google's existing Chrome extension update service, using the store IDs below. The inspection does not establish that every extension feature works.

| Package | Manifest and name result | Runtime evidence and limits |
| --- | --- | --- |
| [Are.na](https://chromewebstore.google.com/detail/arena/lkihjlcipnbgeokmfnpogjfflofbfhga), 2.14.3 | Literal name Are.na. Permissions: `activeTab`, `contextMenus`, `scripting`, `storage`. Uses an in-page extension panel, messaging, storage and programmatic script injection. It does not request cookies or Chrome Google identity. | Its prepared worker starts in a fresh nonpersistent WebKit controller with no package/context errors. Login, saving to a channel, screenshot capture and account session behavior were not tested. |
| [Notion Web Clipper](https://chromewebstore.google.com/detail/notion-web-clipper/knheggckgoiihginacbkhaalnibhilkk), 0.2.20 | `__MSG_webClipperExtension_name__` resolves to Notion Web Clipper from `_locales/en`. | Source inspection identifies cookie access for sign-in. Safience continues denying extension cookie access to protect Google sign-in. Full Notion clipping is not claimed. |
| [Google Translate](https://chromewebstore.google.com/detail/google-translate/aapbdbdomjkkjkaonfhkkikfgjllcleb), 2.0.18 | `__MSG_8969005060131950570__` resolves to Google Translate in English and Google 번역 in Korean. | Its prepared worker starts without package/context errors and receives local `i18n.detectLanguage` output. Real page translation, popup/network behavior and Google accounts were not tested. |

Chrome's [locale lookup and message format](https://developer.chrome.com/docs/extensions/reference/api/i18n) define the name lookup. Are.na's [official extension help](https://help.are.na/docs/getting-started/browser-extension) describes the link, selection and image clipping workflows. Existing requested-site, active-tab, cookies and protected Google sign-in gates remain in force. The text-only language shim called by a content script or an embedded extension panel relays to that extension's own background. A content-only extension without a background cannot use that relay and receives an explicit error; no language-detection success is invented.

## Validation

- Focused package tests: 16 XCTest tests, zero failures. Log: `/private/tmp/safience-extension-names-tests.log`.
- Real public-package names: `/private/tmp/safience-extension-public-names.log`.
- Fresh native workers and real local language endpoint: `/private/tmp/safience-arena-runtime-language.log`, `/private/tmp/safience-translate-runtime-language.log`. Both return `isReliable: true` and an English language result with percentage 100 for a literal test sentence. Earlier measurement confirmed the API was absent before the shim/helper addition.
- Synthetic native clipper harness: [extension-clipper.swift](../Validation/extension-clipper.swift), 7/7 passed. It covers worker/menu registration, the actual local language endpoint, action invocation, programmatic content injection, selected-text messaging, storage, an embedded extension panel and protected-site/cookie gates. Final WebKit context errors are empty. Log: `/private/tmp/safience-extension-clipper.log`; build log: `/private/tmp/safience-extension-clipper-build.log`. An earlier fixture run passed its functional checks but reported its missing synthetic manifest description; completing that metadata removes the diagnostic without changing production gates.
- Parent integration owns the full package suite, final iOS/Mac SDK builds, signed package and release validation. No full account workflow or general Chrome extension compatibility claim follows from these focused checks.
